# 目标

`/am:requirement` 是一个手动触发的产品需求生成命令，用来把用户提供的一句话想法、prompt 或补充说明转换成可交给 UI 设计和前端开发使用的需求包。

## 默认行为

1. 先检查当前项目目录，确认是否已有 `.agent/ui/`、相关需求文档或同名功能目录。
2. 将用户命令参数视为产品想法和约束来源；如果参数里写了目标目录，优先使用用户指定目录。
3. 默认输出到 `.agent/ui/{feature-name}/`，其中 `{feature-name}` 从产品名、功能名或核心场景提取，使用短横线命名。
4. 如果 `.agent/` 不存在，只创建 `.agent/ui/{feature-name}/`，不要顺带初始化其它 `.agent/**` 规则文件。
5. 只生成需求文档，不生成 Pencil 设计稿，不写代码，不修改业务源码。
6. 信息不足时，优先提出最多 3 个关键澄清问题；如果用户要求快速推进，则用明确的假设列表继续生成。

## 输出文件

必须在目标目录生成以下 5 个 Markdown 文件：

- `需求分析.md`
- `线框图.md`
- `设计说明.md`
- `开发说明.md`
- `验收标准.md`

## 文档职责

### 需求分析.md

回答“为什么做、给谁用、做什么、不做什么”。

必须包含：

- 产品定位
- 目标用户
- 核心目标
- 页面范围
- 信息架构
- 核心场景
- 功能需求
- 业务规则
- 页面状态
- 不做范围
- 待确认问题

### 线框图.md

回答“页面结构和流程是什么”。

必须包含：

- 页面清单
- 主导航结构
- 每个页面的区块结构
- 页面跳转关系
- 关键交互
- 空状态、加载态、错误态

### 设计说明.md

回答“Pencil 应该画什么、不要画什么”。

必须包含：

- 设备尺寸
- 页面数量
- 必须设计的页面
- 视觉方向
- 组件要求
- 交互说明
- 设计边界
- 输出期望

### 开发说明.md

回答“根据设计稿应该如何实现页面”。

必须包含：

- 实现目标
- 页面要求
- 模拟数据要求
- 状态要求
- 开发边界
- 推荐实现顺序

### 验收标准.md

回答“什么算完成”。

必须包含：

- 页面覆盖
- 主流程验收
- 交互验收
- 状态验收
- 视觉验收
- 开发验收

## 执行步骤

1. 从用户输入中提取产品名或功能名、平台、目标用户、核心任务、明确约束、目标目录。
2. 如果平台、目标用户或核心场景缺失且会影响页面范围，先做需求澄清。
3. 如果用户要求快速生成，写明假设列表后继续；假设必须保守，不扩展复杂功能。
4. 先定义业务目标和页面范围，再写页面流程、组件、状态和验收标准。
5. 每个页面都要覆盖默认态、空状态、加载态和错误态。
6. 明确不做范围，避免后续设计或开发阶段自行补需求。
7. 如果目标文件已存在，先阅读已有内容；默认更新同一功能目录，不要无提示覆盖用户明确保留的内容。

## 输出要求

最终回复必须说明：

- 需求包输出目录
- 已生成或更新的 5 个文件
- 本次采用的关键假设
- 仍需用户确认的问题
- 后续可执行 `/am:design {feature-name}` 进入 UI 设计
