# 目标

`/am:design` 是一个手动触发的 UI 设计命令，用来根据 `.agent/ui/{feature-name}/` 下的需求文档生成或更新 Pencil 界面设计稿。

## 默认行为

1. 先检查当前项目目录，定位用户指定的需求包目录。
2. 如果用户没有指定目录，优先按 `.agent/ui/{feature-name}/` 查找；只有一个候选目录时可以直接使用，多个候选目录时先要求用户确认。
3. 设计产物默认输出到 `.agent/ui/{feature-name}/{design-source}/`，`{design-source}` 默认为 `codex`；如果用户指定设计来源名称，优先采用用户指定值。
4. 只做 UI 设计，不补业务规则，不写前端代码，不初始化其它 `.agent/**` 规则文件。
5. 需求文档缺失时停止执行，并列出缺失文件；不要基于一句话想法直接跳过需求阶段。

## 输入文件

目标需求包目录必须包含：

- `需求分析.md`
- `线框图.md`
- `设计说明.md`
- `验收标准.md`

建议同时读取：

- `开发说明.md`

## 输出目录

设计产物必须写入：

```text
.agent/ui/{feature-name}/{design-source}/
├── {design-source}.pen
├── images/
├── svg/
└── preview/
```

其中：

- `{design-source}.pen` 是 Pencil 设计稿。
- `images/` 存放设计稿引用的图片资源。
- `svg/` 存放设计稿使用到的 Remix Icon 原始 SVG。
- `preview/` 存放主要页面预览图。

## 设计要求

1. 只根据 `需求分析.md`、`线框图.md`、`设计说明.md` 和 `验收标准.md` 设计，不扩展未定义业务功能。
2. 按 `线框图.md` 覆盖所有页面，按 `验收标准.md` 覆盖关键状态。
3. 先保证页面结构、状态和交互完整，再处理视觉层级和组件细节。
4. 输出高保真界面，不做营销页，不把页面画成概念图。
5. 组件命名要清晰，同类组件保持一致。
6. 图标优先使用 Remix Icon；不要用文本符号、临时形状或手绘几何图形假装正式图标。
7. 如果 Pencil `.pen` 不能稳定导出 SVG，不要从 `.pen` 反向解析 SVG；应记录使用的 Remix Icon 名称，并从官方图标源直接输出到 `svg/`。
8. 如果可用图标库或 Pencil 工具不可用，先停止并说明阻塞，不要用替代符号糊弄产物。

## 执行步骤

1. 读取需求包目录，确认输入文件齐全。
2. 从 `设计说明.md` 提取设备尺寸、页面数量、视觉方向、组件要求和设计边界。
3. 从 `线框图.md` 提取页面结构、导航关系、关键交互和状态覆盖。
4. 使用 Pencil 创建或更新 `{design-source}.pen`。
5. 将引用图片写入 `images/`，将 Remix Icon 原始 SVG 写入 `svg/`，将主要页面预览导出到 `preview/`。
6. 对照 `验收标准.md` 自查页面齐全度、主流程闭环、状态覆盖、组件一致性、文案一致性和明显对齐/溢出/遮挡问题。

## 输出要求

最终回复必须说明：

- 使用的需求包目录
- 设计稿输出路径
- 预览图输出目录
- 使用到的关键图标或图片资源
- 验收自查结果
- 是否存在未完成或阻塞项
