# 目标

`/am:plan` 是一个手动触发的 AI SOP 命令，只在用户明确调用时生效。

## 默认行为

1. 先检查当前项目代码、目录结构、规则文件与已有实现。
2. 再做上下文梳理，不直接改代码。
3. 先输出 SOP，再决定是否进入实现。
4. 只有当用户在命令里明确要求“边计划边实现”时，才进入落地阶段。

## 标准 SOP 流程

### 1. 调研

需要完成：

- 明确任务目标、边界、输入输出
- 检查项目现状、技术栈、已有实现
- 找到需要优先阅读的规则文件与代码目录
- 标记已确认项、待确认项、风险项

### 2. 拆任务

需要完成：

- 将任务拆成可执行步骤
- 标出每一步涉及的文件、目录、模块
- 标出依赖项、阻塞项、可并行项
- 给出最小可交付范围，避免过度实现

### 3. 实施

需要完成：

- 说明每一步准备怎么改
- 明确新增、修改、删除分别落在哪些文件
- 如果命中接口、常量、公共方法，明确需要同步哪些索引或文档
- 如果用户明确要求边计划边实现，再进入落地

### 4. 自检

需要完成：

- 说明要跑哪些检查、测试、构建或静态校验
- 如果进入实施并修改了代码，对本次修改文件执行 lint 校验，优先按文件路径或最小范围运行
- 检查命名、代码顺序、索引同步、文档同步
- 检查是否存在多余实现、无效注释、无语义缩写

### 5. 交付

需要完成：

- 输出最终变更摘要
- 输出验证结果
- 输出剩余风险与后续建议
- 如果未执行某些检查，要明确说明原因

## 输出格式

`/am:plan` 的输出至少包含以下 5 段：

1. 调研
2. 拆任务
3. 实施
4. 自检
5. 交付

每一段都要写清：

- 目标
- 输入
- 输出
- 风险或注意事项

## 文档读取顺序

1. 先看 `AGENTS.md`、`CLAUDE.md`
2. 命中具体场景后，再看对应详细文件
3. 如果要做接口任务，补读 `.agent/api.md`
4. 如果要做常量任务，补读 `.agent/index/constants.json`
5. 如果要做公共方法任务，补读 `.agent/index/utils.json`
6. 收尾阶段读取 `.agent/scripts/lint.md`

## 索引与文档协同

如果任务涉及以下内容，计划里要显式写出同步动作：

- 接口变更：同步项目侧索引或根文档中涉及的项目约定，不要修改共享规则软链接 `.agent/api.md`
- 常量或枚举变更：同步 `.agent/index/constants.json`
- 公共方法变更：同步 `.agent/index/utils.json`
- 收尾规则：同步 `.agent/scripts/lint.md`

## admin 额外要求

如果识别为 admin 项目，计划里必须显式写出：

- 删除未使用变量
- 删除未使用导入
- 删除未使用参数或无意义占位变量
- 完成后再做一次收尾检查
