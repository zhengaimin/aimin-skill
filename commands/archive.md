# 目标

`/am:archive` 手动从当前项目、已有资料和用户 prompt 中提取关键点，生成中文 Markdown 归档到 `.agent/archive/`。这个命令只服务后续实现、排查、计划和交接，不写长篇背景，不补未确认信息。

## 核心规则

1. 只整理关键点：每条信息必须能影响实现、验收、排查、风险判断或后续修改。
2. 内容只按功能点和页面归口；其它问题归入更接近的一类，不再按英文子目录拆分。
3. 正文优先使用 Markdown 表格，保留结论、约束、影响、涉及文件和待确认事项。
4. 先检查当前项目的 `AGENTS.md`、`.agent/archive/`、`.agent/archive/README.md` 和现有归档；`.agent/docs/` 只读，只存客户、后台、产品方给的原始资料。
5. 如果 `.agent/archive/` 不存在，只创建归档所需目录；不要初始化其它 `.agent/**` 规则文件。
6. 默认先查找并更新对应归档文件；只有找不到对应文件时才新建稳定主题文件。
7. 后续修改对应功能点或页面前，必须先读取相关归档文档；找不到精确文档时先读 `.agent/archive/README.md`。
8. 如果本次包含代码修改，先读取对应归档文档和用户 prompt 进行确认，再修改代码；改完回写到对应归档文档，记录关键变更、影响和待确认事项。
9. 不要把归档写入 `.agent/docs/`，不要修改 `CLAUDE.md`、`.agent/index/**` 或其它无关规则文件。

## 文件落点

归档不是按日期新建流水文档，而是按核心规则落到对应文件中。

| 场景 | 处理方式 |
| --- | --- |
| 已有对应归档文件 | 直接更新该文件，补充本次提取的关键点、影响和待确认事项 |
| `AGENTS.md` 项目级规则表已登记对应文件 | 先读取登记的归档文件，再按本次 prompt 更新 |
| `.agent/archive/README.md` 能索引到对应文件 | 先读取索引指向的归档文件，再按本次 prompt 更新 |
| 找不到对应文件 | 按功能点或页面的稳定主题新建文件，例如 `.agent/archive/order-detail.md`，不要使用日期前缀 |

新建文件名必须来自明确的功能点或页面名称，使用短横线命名；没有清晰主题时先从用户 prompt 和项目上下文提炼主题，不要生成日期前缀流水文件。

## 文档结构

归档文档按需包含这些部分，信息不足时在“待确认事项”说明缺口：

| 部分 | 建议内容 |
| --- | --- |
| 主题 | 功能点或页面名称、来源 |
| 关键结论 | 已确认且后续必须参考的要点 |
| 决策与约束 | 决策、规则、边界、影响范围 |
| 涉及文件或模块 | 路径或模块、作用、修改前是否必读 |
| 待确认事项 | 缺口、原因、当前状态 |
| 后续动作 | 顺序、动作、备注 |

## AGENTS.md

只有归档内容需要成为“修改前必读”规则时，才同步维护 `AGENTS.md` 的 `## 项目级别规则` 表格，固定列为 `修改范围 / 对应归档文档 / 读取要求 / 备注`：

| 修改范围 | 对应归档文档 | 读取要求 | 备注 |
| --- | --- | --- | --- |

## 输出要求

- 已生成或更新的归档路径
- 本次归档落点：更新已有文件或新建稳定主题文件
- 本次提取的关键点摘要
- 是否更新 `AGENTS.md` 项目级规则表
- 是否存在待确认事项
